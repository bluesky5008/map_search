# DCR-001: 게임 줌 렌더링 제약에 따른 MODE-A 재정의

- 상태: **승인** (2026-08-02) — 채택안: **안 1(A1/A2 분리), 단 v1은 A2만 구현하고 A1은 후속**
- 발견 위치: Workflow 2, 스파이크 S-2 (P-01 검증), S-2b/S-2c (창 종횡비)
- 현재 설계 기준선: 요구사항 v1 / 설계 v1 (2026-08-01 승인) → **새 기준선 v2 (2026-08-02)**
- 관련 요구사항: FR-03, FR-05, NFR-01, NFR-02
- 관련 ADR: ADR-004(모드 구조 — 유지), **ADR-005(창 크기·종횡비 정책 — 신규)**

## 변경 사유와 증거

스파이크 S-2 실기 검증 결과, 게임 클라이언트의 줌 렌더링이 기준선 가정과 다르다.

- **전략 뷰(광역 줌):** 중립 타일(자원·공터)을 아예 렌더링하지 않는다. 점령 타일 색상, 소유 건물, 지형만 표시된다. 증거: `spikes/s2_zoom_grid/work/s2_01_out3.png`, `s2_02_out8.png` — S-1b에서 `Lv.5 목재`로 확인된 위치가 전략 뷰에서 맨 풀밭으로 표시됨.
- **디테일 줌:** 중립 자원은 종류별 스프라이트(나무=목재, 바위=석재)로 식별 가능하나, 화면당 타일 수 상한이 \~35-40개다. 증거: `s2_pop_trees.png`(Lv.5 목재), `s2_pop_rocks.png`(Lv.4 석재), `s2_pop_plain.png`(공터).

결과적으로 기준선의 "MODE-A로 대분류+자원 종류+점령상태를 전체 맵에서 반나절 내 수집"(FR-03 + NFR-02)은 동시에 충족할 수 없다. 자원 종류를 얻으려면 디테일 줌 순회가 필요하고, 1600×1600 기준 예상 소요는 **약 32\~52시간**이다(화면당 유효 \~55타일 → 방문 \~46,500회 × 2.5\~4초).

**창 크기 최적화 효과(S-2b/S-2c 검증):** 게임은 월드 렌더 배율을 **창 높이**에 맞추므로 가시 타일 수 ∝ 종횡비(W/H)다.

- 종횡비를 유지한 확대(1294x758 → 2560x1440)는 효과 없음: 가시 타일 85 → 89.
- **사분면 스냅(클라이언트 2544x657, 종횡비 3.87)은 가시 타일 246개로 약 2.9배** — 클릭 좌표 판독으로 확정.
- 이에 따라 MODE-A2(디테일 줌 전체 스캔) 예상 소요가 **32\~52시간 → 10\~15시간**으로 단축된다. A2의 실용성이 크게 개선되어 안 1의 가치가 높아진다.
- 제품은 시작 시 창을 사분면 크기(예: 작업영역 1/4)로 설정한다. NFR-02(반나절 목표)를 A2에도 조건부로 적용할 수 있다.

## 기존 설계

- MODE-A: 광역 줌 1패스로 전체 맵의 대분류·자원 종류·점령상태 수집, 목표 반나절(NFR-02).

## 제안 설계 (안 1, 권장)

MODE-A를 두 개의 서브패스로 재정의하고 각각 독립 실행 가능하게 한다. ADR-004의 전략 패턴 구조는 그대로 유지되며 서브패스는 ScanMode 구현 2개로 표현한다.

- **MODE-A1 (전략 줌 패스):** 전체 맵을 전략 뷰로 순회. 수집 정보 = 점령상태(5색), 소유 건물(주성·분성 등 렌더 대상), 지형(강·산). 중립 타일은 `중립-미상`으로 기록. 목표 소요: 반나절 이내(NFR-02는 A1에만 적용).
- **MODE-A2 (디테일 줌 패스):** 전체 맵(또는 지정 영역)을 디테일 줌으로 순회. 수집 정보 = A1 + 자원 종류(목재·철광·석재·식량·구리)·공터·1칸건물. 레벨은 여전히 미수집(클릭 필요, MODE-B/C 영역). 예상 소요: **사분면 스냅 창 기준 10\~15시간**(1600²) — 체크포인트 재개로 분할 실행 가능.

### 검토한 대안

- **안 2 — MODE-A를 디테일 줌 전체로 단일화:** 산출은 완전하나 최소 수 일 소요. NFR-02를 "수 일"로 완화해야 하며 빠른 점령 지도 용도가 사라짐.
- **안 3 — MODE-A를 전략 줌만으로 축소:** 반나절 목표는 지키지만 자원 종류가 MODE-B/C 구현 전까지 전혀 수집되지 않음.

안 1은 두 용도(빠른 점령 지도 / 완전한 토지 지도)를 모두 보존하고 사용자가 실행 시점에 선택하게 한다.

### 채택 결정 (2026-08-02, 사용자 승인)

**안 1 채택. 단 v1 구현 범위는 MODE-A2만으로 하고 MODE-A1은 후속 단계로 미룬다.**

근거:
- A2가 A1 정보의 상위 집합(점령상태도 디테일 뷰에서 판독 가능)이므로, A2를 먼저 구현하면 v1이 요구사항을 온전히 충족한다.
- A1은 "기존 지도의 점령 정보만 빠르게 갱신"하는 최적화이며, 그 가치는 A2 지도를 실제로 만들어 본 뒤에 판단하는 편이 낫다.
- A1의 예상 소요(2\~4시간)는 전략 뷰 화면당 타일 수 추정에 기반한 미실측 값이라, 구현 전 확인이 필요하다.
- 결과적으로 v1 작업량은 안 2와 같으면서, 설계는 ADR-004의 전략 패턴 덕분에 A1을 나중에 추가할 수 있는 구조로 남는다.
