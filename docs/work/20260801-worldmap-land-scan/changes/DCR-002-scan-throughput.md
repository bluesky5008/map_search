# DCR-002: 실측 처리량이 NFR-02(스캔 소요) 목표에 미달

- 상태: **승인 (안 d)** (2026-08-02, 승인자: 사용자)
- 발견 위치: Workflow 2, T12(nav 계층) 실기 검증
- 현재 설계 기준선: 요구사항 v2 / 설계 v2 (2026-08-02 승인, DCR-001)
- 관련 요구사항: **NFR-02**(스캔 소요), FR-03b, AC-05
- 관련 ADR: ADR-005(창 종횡비 — 유지), ADR-004(모드 구조 — 유지)
- 관련 위험: R-09(신규)

## 변경 사유와 증거

NFR-02는 MODE-A2 전체 스캔을 **하루 이내**로 규정하고 "실측으로 확정한다"고 단서를 달았다. T12에서 실측한 결과 목표를 크게 초과한다.

증거: `spikes/s3_nav_ui/findings.md`, `spikes/s3_nav_ui/work/live_check.log` (계정 2개에서 재현)

| 항목 | NFR-02 근거(DCR-001 추정) | T12 실측 |
|---|---|---|
| 화면당 가시 타일 | 246 (HUD 제외 유효 185) | 199 |
| HUD·선택 팝업 제외 후 커버 오프셋 | — | **56** |
| 방문당 신규 커버 타일 | 185 | **36** (보폭 6×6) |
| 맵 크기 | 1600² 가정 | **1619² 실측(자동 감지)** |
| 방문 횟수 | 13,900 | **72,900** |
| 방문당 소요 | 2.5~4초 | **7.7초** (점프 4.3 + 분류 3.4) |
| **총 소요** | **10~15시간** | **약 150시간** |

### 왜 이렇게 벌어졌는가

1. **오클루전이 커버 영역을 크게 깎는다.** 좌표 점프 직후 뜨는 선택 팝업이 클라이언트 좌표계에서 약 760×440px를 가린다. 우측 부대 패널·상단 자원바·하단 메뉴까지 더하면 가시 199타일 중 56타일만 분류에 쓸 수 있다.
2. **커버 집합에 구멍이 있어 타일링 보폭이 작아진다.** 방문당 커버 영역은 사각형이 아니라 구멍 뚫린 모양이다. 시프트한 커버 집합들이 평면을 빈틈없이 덮으려면 잉여류 조건(오프셋들의 (mod sx, mod sy)가 sx·sy 클래스를 모두 덮음)을 만족해야 하고, 실측 커버 집합에서 최대 보폭은 6×6 = **36타일/방문**이다. 커버 56개를 전부 활용하지 못한다.
3. **방문당 소요가 가정의 2배다.** 좌표 점프는 지도 모드 진입과 이동, 두 번의 화면 전환을 포함한다.

### 이미 확인한 제약

- **선택 팝업은 닫을 수 없다(S-4).** ESC는 팝업이 아니라 "게임을 종료하시겠습니까?" 확인 창을 띄운다. 설계 §4.3의 "인접 방문 겹침으로 커버"(P-06) 전제는 유지되지만, 그 겹침 비용이 위 수치다.
- 창 종횡비 최적화(ADR-005)는 이미 반영된 상태의 수치다. 추가 종횡비 확대는 실기에서 창 겹침·캡처 오염으로 측정하지 못했다(S-2c).

## 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **(a)** | NFR-02 완화 (예: MODE-A2 = 2~3일) | 설계·구현 변경 없음 | 무인 장시간 실행 부담, 스냅샷 일관성 저하(A-01) |
| **(b)** | v1 범위를 MODE-A1(전략 뷰)로 축소 | 소요 대폭 감소 | 자원 종류를 못 얻는다 — DCR-001에서 부족하다고 판단해 A2를 택한 결정을 되돌림 |
| **(c)** | 전체 맵 대신 지정 영역 한정 스캔 | 소요를 사용자가 통제 | 전 좌표 커버(AC-05) 포기 |
| **(d)** | **최적화 후 재측정** (권고) | 목표 범위 복귀 가능성 | 최적화 실패 시 시간 손실 → 스파이크 게이트로 위험 통제 |

## 제안 (안 d, 권장)

세 가지 최적화를 순서대로 적용하고 재측정한다.

| 순위 | 최적화 | 기대 효과 | 위험 |
|---|---|---|---|
| 1 | **이동을 좌표 점프 → 드래그 팬으로 전환** | 화면 전환 2회(약 3초) 제거 + **선택 팝업 미발생** → 커버 오프셋 56→90, 보폭 4×14=56타일/방문. 방문 72,900→약 29,000, 방문당 약 2초 → **약 16시간** | 팬 동작 미검증, 누적 드리프트 |
| 2 | 분류 대상을 신규 커버 타일로 한정(199→36~56) | 3.2초 → 약 0.8초 | 없음(계산 범위 축소) |
| 3 | HUD 사각형을 실제 불투명 영역으로 축소 | 커버 오프셋 추가 증가 | 오클루전 오판 시 오분류 → 경계에 여유 유지 |

**게이트 조건:** 최적화 1은 미검증이므로 짧은 스파이크 **S-5**로 먼저 확인한다.

- 드래그로 지도가 팬되는가 (PostMessage 드래그가 클라이언트에 전달되는가)
- 1회 드래그당 이동량이 재현 가능한가 (분산, 감속·관성 유무)
- 연속 팬의 누적 드리프트가 주기적 재앵커링으로 흡수 가능한가

통과하면 (d)로 진행하고, 실패하면 **(a)로 전환**한다. 팬을 쓰더라도 드리프트 보정을 위해 행 시작마다 좌표 점프로 재앵커링하는 하이브리드를 전제한다.
