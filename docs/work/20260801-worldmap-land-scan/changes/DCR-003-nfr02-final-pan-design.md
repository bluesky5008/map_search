- 상태: **승인** (2026-08-02, 승인자: 사용자 — 권고안 48시간 채택)
- 발견 위치: Workflow 2, DCR-002 안 (d) 후속 (S-5 스파이크 + S-6 재측정)
- 현재 설계 기준선: 요구사항 v2 / 설계 v2 (2026-08-02, DCR-001)
- 관련 요구사항: **NFR-02**(요구사항 변경), FR-03b·AC-05(영향 없음 확인)
- 관련 DCR: [DCR-002](DCR-002-scan-throughput.md) 승인(안 d) — 본 DCR이 그 후속 절차
- 관련 ADR: ADR-002(캡처·입력 — 유지, 팬 입력도 PostMessage), ADR-005(창 종횡비 — 유지)

## 변경 사유와 증거

DCR-002 승인 조건에 따라 스파이크 S-5(드래그 팬 실현 가능성)를 통과시키고
([findings](../../../spikes/s5_drag_pan/findings.md)), 최적화 3종(팬 전환·대역
한정 분류·HUD 축소)을 적용해 방문 99회를 연속 실측했다
([S-6 findings](../../../spikes/s6_remeasure/findings.md)).

| 방문 유형 | 방문당 소요 | 방문당 신규 커버 |
|---|---|---|
| 행 시작 점프(재앵커) | 6.70s | 51.0타일 |
| 광폭 팬(1900px) | **2.95s** | **68.2타일** |

**총 소요(1620² = 2,624,400타일): 33~36시간** (행당 팬 10회 실측 36.4h,
행 연장 상각 시 33.1h, 점근 31.5h). 좌표 점프 단독(150시간) 대비 4.2~4.6배
개선이나, NFR-02 원문 "하루 이내(24시간)"에는 여전히 미달한다.

미실증 개선 여지(분류 소요 축소, 대역 확대)로 약 23시간까지 기대할 수 있으나
실측되지 않았으므로 목표 수치의 근거로 쓰지 않는다(실측 우선 원칙).

## 기존 요구사항 (v2)

> NFR-02: 전체 맵 스캔 소요 목표: MODE-A2는 **하루 이내**(사분면 스냅 창 전제,
> 1600² 기준 10~15시간 추정), MODE-A1은 반나절 이내. 실측으로 확정한다.

## 제안 요구사항 (v3)

> NFR-02: 전체 맵 스캔 소요: MODE-A2는 **48시간(2일) 이내**(사분면 스냅 창,
> 팬 이동 전략, 1619² 실측 기준선 33~36시간 + 중단·복구 마진). 스캔은 중단·재개
> 가능해야 하며(NFR-03, FR-07 연계) 단일 무중단 실행을 전제하지 않는다.
> MODE-A1(후속 범위)은 반나절 이내 추정 유지 — 구현 시 실측으로 확정한다.

**대안** (사용자 선택):

| 안 | 수치 | 비고 |
|---|---|---|
| **(권고)** | 48시간 이내, 기준선 33~36시간 | 실측 + 워치독·복구·게임 이벤트 중단 마진. 스냅샷 일관성 저하(A-01)는 도메인상 허용(토지 정보 변화는 느림)을 명시 |
| 긴축 | 36시간 이내 | 실측 상한과 같음 — 운영 마진 없음, 중단 1회로 초과 위험 |
| 유지 | 24시간 이내 | 미실증 최적화(분류 5.5ms/타일, 대역 400px) 달성을 전제로 해야 함 — 실측 우선 원칙과 충돌 |

## 변경 항목 (설계 v3)

| 항목 | 기존 (v2) | 변경 | 이유·근거 |
|---|---|---|---|
| §2 Navigator | 좌표 점프가 유일한 이동 | 점프(행 시작 재앵커) + **드래그 팬(행 내 주 이동)**. 팬 전 화면 검증은 지도 마커가 아니라 **디테일 뷰 시그니처**(계정 HUD) — 점프 완료 후 게임은 지도 UI를 닫는다(S-5 발견 1) | S-5 G1·G2 |
| §2 ScanPlanner | 잉여류 타일링 방문 계획 | **행 기반 계획**: 행 = 점프 1 + 팬 N. 팬 이동량은 계획값이 아니라 실측·누적(전단 추적) | S-5 발견 3 |
| §4.3 스캔 루프 | 방문마다 jump → 전체 가시 타일 분류 | 행 시작만 jump. 팬 프레임은 **y 대역(≈280px) 신규 진입 셀만 분류**(커버 집합 중복 제거). 팬 이동은 전폭 밴드 3개의 x 이동을 dx(y)=a+b·y로 적합해 추적 — 이동장이 화면 y에 선형(원근 지면)이기 때문. **기대 게인 창(±80px) 밖 밴드는 기각**(눈 지형 오추적 실측) | S-5 발견 3, S-6 관찰 1 |
| §4.3 팝업 처리 | 모든 방문 프레임에 팝업 오클루전 | 팝업은 **행 시작 프레임에만** 존재(첫 팬에서 소멸, S-5 G1). 팝업 사각형은 실측값(타일 중심 상대 −290,−215 ~ +370,+150)으로 갱신 — 기존 값은 우측 버튼 열(+355px)을 놓침 | S-5 발견 2 |
| ui.py HUD 상수 | HUD_RECTS_CLIENT 6개(보수적) | 실측 불투명 영역으로 축소(S-6 `HUD_REFINED`) — 우측 패널 520→380, 하단 밴드 495→540 등 | S-6 |
| §5 성능 | 방문 13,900회 × 2.5~4s = 10~15h 추정 | 행 기반: 팬 방문당 2.95s·68.2타일 실측 → **33~36시간** | S-6 |
| NFR-02 | 하루 이내 | 위 제안 요구사항 | S-6 |

FR-03b(자원 종류·레벨), AC-05(전 좌표 커버), AC-02(점령상태)는 영향 없다 —
팬 전환은 이동 수단만 바꾸며 분류 경로·커버 보장(커버리지 비트맵 보충)은 유지된다.

## 영향 범위

- 요구사항: NFR-02 (v3). 그 외 항목 변경 없음.
- 설계: §2 Navigator·ScanPlanner, §4.3, §5, UI 캘리브레이션 상수.
- 구현: **T13 ScanController**가 행 기반 루프·전단 추적·밴드 기각을 구현한다.
  S-6 하네스(`spikes/s6_remeasure/measure100.py`)가 검증된 참조 구현이다.
- T14 추가 항목: 겨울(눈) 테마 팝업 좌표 글리프 템플릿 보강(S-5 발견 6),
  광폭 팬 추적 이상치 기각 검증, 기저 y-의존 실측(대역 확대 여부 판단).

## 구현된 코드의 처리

- T11 vision·T12 nav 전부 유지(점프는 행 시작 재앵커로 그대로 사용).
- `PostMessageInput.drag()` 검증 완료 — 제품 경로로 승격.
- S-5/S-6 스파이크 코드는 스파이크로 보존, 검증된 로직(전단 추적·대역 열거·
  디테일 뷰 시그니처)은 T13에서 제품 코드로 이식한다.

## 마이그레이션 및 롤백

- 수집 데이터 없음 → 마이그레이션 불필요.
- 팬 경로에 문제가 생기면 좌표 점프 단독 경로가 그대로 남아 있어 즉시 롤백
  가능(소요는 150시간으로 복귀 — NFR-02 재협의 필요).

## 검증 방법

- T13 완료 후 단위: 행 계획 생성·전단 추적 적합·밴드 기각·커버 중복 제거.
