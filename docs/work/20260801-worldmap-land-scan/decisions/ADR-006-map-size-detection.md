# ADR-006: 맵 크기 감지 — 글리프 OCR 대신 클램프 렌더링 이미지 비교

- 상태: **승인 (v2 구현)** — T12 실기 검증 완료 (2026-08-02)
- 날짜: 2026-08-02
- 관련 요구사항: FR-02 (맵 최대 좌표 자동 감지), 인수 조건 AC-05
- 관련 설계: §2 Navigator·DigitReader, §4.2
- 관련 검증 항목: **P-03 실패** (`spikes/s3_nav_ui/findings.md`)

## 배경

설계 §4.2는 좌표 입력란에 `9999`를 넣어 게임이 실제 최대 좌표로 강제 변경(클램프)하게 한 뒤, 그 값을 `DigitReader`의 글리프 템플릿 매칭으로 판독해 맵 크기를 확정하도록 규정했다. 판독 실패 시(P-03 실패) 사용자 수동 입력으로 대체하는 폴백도 함께 규정되어 있다.

T12 실기 검증에서 **P-03이 실패**했다. 좌표 입력란 폰트는 팝업 좌표 폰트와 달라 숫자 글리프가 서로 붙어 있고, 연결 성분 기반 글리프 분리가 성립하지 않는다(예: "12345"에서 "45"가 한 덩어리로 잡힘). 텍스트 커서까지 성분으로 섞인다.

수동 입력 폴백만 남기면 FR-02("자동 감지한다")를 충족하지 못한다.

## 고려한 대안

1. **입력란 전용 글리프 템플릿을 추가하고 분할 알고리즘을 강화** — 폰트 폭 기반 강제 분할, 슬라이딩 윈도우 매칭 등. 구현·튜닝 비용이 크고, 게임 업데이트로 폰트가 바뀌면 다시 깨진다.
2. **클램프 렌더링 이미지 비교 + 이진 탐색** (채택) — 값을 읽지 않고, "이 값이 클램프되었는가"만 판정한다. `clamp(v) = min(v, max)`이므로 v의 렌더링이 상한(9999)의 렌더링과 같아지는 **최소 v가 곧 max**다. 0\~2047 범위에서 이진 탐색 11회.
3. **수동 입력만 제공** — FR-02 미충족.

## 결정

**대안 2를 채택한다.** `Navigator.detect_map_size()`는 축마다 다음을 수행한다.

1. 입력란에 상한값(기본 9999)을 넣고 **반대 필드를 클릭해 블러**시킨다. 클램프는 포커스가 빠질 때 적용된다(실측).
2. 숫자 영역을 캡처해 기준 렌더링으로 삼는다.
3. 후보 v에 대해 같은 절차로 렌더링을 얻고 기준과 픽셀 비교한다. 같으면 `v >= max`, 다르면 `v < max`.
4. 이진 탐색으로 경계를 찾는다.

`DigitReader`는 폐기하지 않는다. 팝업 좌표 문자열(공백으로 분리된 폰트)에서는 정상 동작하며, MODE-B/C의 `PopupReader`에서 계속 쓴다.

## 이유

- **폰트에 의존하지 않는다.** 글리프 분리·템플릿·임계값이 전혀 필요 없으므로 게임 업데이트로 폰트나 자간이 바뀌어도 동작한다(위험 R-03 완화).
- **판정이 이진이라 오류가 조용히 전파되지 않는다.** OCR은 한 글자를 틀리면 그럴듯한 잘못된 값을 내지만, 이미지 비교는 같음/다름만 판단한다.
- 비용이 작다. 축당 11회 × 약 2초 = 약 20초, 스캔 시작 시 1회만 수행한다. 실측 총 39.7\~42.3초.

## 결과와 단점

- 스캔 시작 시 약 40초의 고정 비용이 생긴다. 전체 스캔 시간에 비하면 무시할 수준이다.
- 입력란에 값을 넣는 조작이 반복되므로 **오클릭 위험이 커진다.** 지도 모드가 아닐 때 같은 좌표를 클릭하면 선택 팝업의 '점령·행군' 버튼을 누를 수 있다(T12 실기 사고). 이에 따라 `Navigator`는 **매 클릭 전에 지도 모드 마커를 확인**하고, 아니면 `NotInMapMode`로 중단한다.
- 입력란 조작에는 다음 실측 제약이 따른다.
  - `WM_CHAR`로 보낸 백스페이스(`\b`)는 무시된다. `WM_KEYDOWN/UP` + `VK_BACK`을 써야 한다.
  - 백스페이스는 커서 왼쪽만 지우므로 **`VK_END`를 먼저 보내야** 한다. 생략하면 잔여 문자가 남아 엉뚱한 좌표로 이동한다(실제 발생).
- 이미지 비교 임계는 안티에일리어싱 수준의 차이만 허용하는 엄격한 값을 쓴다. 읽는 시점에는 포커스가 없어 텍스트 커서가 없으므로 성립한다.

## 검증

- 단위: `tests/test_nav_navigator.py::DetectMapSizeTest` — 클램프를 모사한 가짜 클라이언트에서 정사각(1619)·비대칭(1200×800)·소형(7×3) 맵을 모두 맞춘다.
- 실기: 계정 2개(컬러단장용스·羊커리)에서 **(1619, 1619)** 감지, 각 39.7초·42.3초. 육안 판독값과 일치.
