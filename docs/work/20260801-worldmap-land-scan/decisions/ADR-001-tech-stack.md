# ADR-001: 구현 언어·스택 — Python + OpenCV

- 상태: 승인 (2026-08-01, 기준선 v1)
- 날짜: 2026-08-01
- 관련 변경 요청: 최초 설계

## 배경

요구사항은 개발 언어에 제한을 두지 않는다(시스템 구성 3). 필요한 능력은 ① Windows 창 캡처·입력 자동화 ② 템플릿 매칭 중심의 이미지 인식 ③ SQLite/CSV 저장 ④ 장시간 배치 실행이다. 안드로이드 버전은 완료 이후 별도 단계다(NFR-05).

## 고려한 대안

1. **Python 3.12 + OpenCV + pywin32 + winsdk(WGC)** — CV 생태계 최강, 개발 속도 빠름, 배포는 PyInstaller 단일 exe.
2. **C# (.NET 8, WPF/콘솔)** — Windows Graphics Capture 네이티브 지원이 매끄럽고 배포 용이. OpenCVSharp 의존, CV 실험 반복 속도는 Python보다 느림.
3. **C++** — 성능 최상이나 개발 비용 과다. 본 작업의 병목은 CPU가 아니라 게임 화면 전환 대기라 이점이 작다.

## 결정

Python 3.12 + OpenCV(템플릿 매칭·색상 판별) + pywin32(Win32 창·입력) + winsdk 또는 windows-capture(WGC) + 표준 sqlite3. 배포는 PyInstaller.

## 이유

- 인식 파라미터(임계값·템플릿) 튜닝의 반복 속도가 프로젝트 성패를 좌우하며, Python이 이 반복이 가장 빠르다.
- 처리량 병목은 화면 전환 대기(방문당 ~2.5초)로, 언어 성능 차이가 전체 시간에 거의 영향을 주지 않는다.
- 안드로이드 단계는 어떤 언어를 골라도 캡처·입력 계층의 재작성이 필요하므로, 인식 로직의 인터페이스 분리(설계 §6)로 대비하고 언어 통일을 강제하지 않는다.

## 결과와 단점

- 단일 exe 패키징 크기가 큼(수십 MB) — 개인 도구이므로 수용.
- WGC의 Python 바인딩은 C#보다 성숙도가 낮음 — S-1 스파이크에서 조기 검증하고, 문제 시 캡처 모듈만 C# 헬퍼 프로세스로 분리하는 대안을 유지한다.
