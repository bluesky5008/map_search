# ADR-002: 캡처·입력 방식 — WGC + PostMessage 기본, 전면 제어 폴백

- 상태: 승인 — **S-1 스파이크 통과로 확정** (2026-08-01). 가림 상태에서 WGC 캡처·PostMessage 클릭 모두 실기 검증 완료(`spikes/s1_background_io/findings.md`). 전제: 게임이 관리자 권한 실행 중이면 도구도 관리자 권한 필요(UIPI). 캡처 대상은 HWND 기준 바인딩.
- 날짜: 2026-08-01
- 관련 변경 요청: 최초 설계, 사용자 결정 Q-04(백그라운드 동작 필요)

## 배경

사용자는 스캔 중 게임 창이 가려져 있어도 동작하기를 요구했다(NFR-06). 게임 클라이언트는 GPU 렌더링을 사용하므로 고전적 GDI 캡처(BitBlt)는 가림 상태에서 실패할 수 있고, 합성 입력도 포커스 요구 여부가 클라이언트 구현에 따라 다르다.

## 고려한 대안

1. **Windows Graphics Capture(WGC) + PostMessage** — WGC는 창이 가려져도(최소화 제외) 프레임을 제공한다. PostMessage 마우스 이벤트는 클라이언트가 표준 메시지 루프로 입력을 받는 경우 비활성 창에도 전달된다. 게임이 Raw Input/포커스 검사를 쓰면 실패.
2. **전면 제어(BitBlt/mss + SendInput)** — 가장 확실하나 스캔 동안 PC 점유. 사용자 1순위 요구와 상충, 폴백으로만.
3. **가상 머신/원격 세션에 클라이언트 격리** — 확실한 백그라운드화가 가능하나 사용자 환경 구축 부담이 큼. 범위 밖으로 유지하되 1안 실패 시 사용자에게 선택지로 제시.

## 결정

`ICapture`/`IInput` 인터페이스 아래 1안(WgcCapture + PostMessageInput)을 기본 구현, 2안(BitBltCapture + SendInput)을 폴백 구현으로 둔다. 시작 시 프로브(§4.1)로 동작 여부를 자동 판정하고, 실패 시 사용자 확인 후 폴백 전환한다. S-1 스파이크로 실제 클라이언트에서의 동작을 구현 착수 직후 판정한다.

## 이유

- 사용자 요구(백그라운드)를 충족할 수 있는 유일한 저비용 경로가 1안이다.
- 실패 가능성이 실재하므로(게임별 편차) 인터페이스 분리 + 자동 프로브 + 합의된 폴백으로 위험을 흡수한다.

## 결과와 단점

- 구현이 두 벌(기본+폴백)이 되어 초기 비용 증가 — 인터페이스가 좁아(캡처 1메서드, 클릭·키입력·휠) 수용 가능.
- PostMessage 좌표는 클라이언트 좌표계 기준이므로 DPI·창 테두리 보정을 WindowSession에서 일원화해야 한다.
- 창 최소화 상태는 WGC도 프레임을 갱신하지 않으므로 지원 범위에서 제외한다(요구사항 §6 NFR-06에 명시).

## 구현 실측 보완 (2026-08-02, T12)

이 ADR의 결정은 유지되며, 아래는 그 구현 시 반드시 지켜야 할 사항이다.

- **캡처 바인딩은 `window_hwnd`로 한다.** S-1은 "캡처 세션은 HWND 기준 바인딩"을 규정했으나 초기 구현은 `windows-capture`의 제목 매칭에 z-raise를 더한 우회였다. 이 방식은 **같은 제목·같은 크기의 다른 창을 조용히 잡는다** — T12에서 입력은 A창에, 화면은 B창을 보는 상태로 30분간 오진단했다. 프레임 크기 검증(`BIND_TOLERANCE`)은 같은 크기 창을 구분하지 못하므로 보조 수단일 뿐이다. `windows-capture` 2.x의 `window_hwnd` 인자를 쓴다.
- **창 식별 수단이 필요하다.** HWND는 클라이언트 재시작 시 바뀐다. `mapscan windows --crops <디렉터리>`가 창별 계정명 영역을 저장해 어느 HWND가 어느 계정인지 확인하게 한다.
- **키 입력은 `WM_CHAR`만으로 부족하다.** 백스페이스를 `WM_CHAR('\b')`로 보내면 무시된다. 편집 키는 `WM_KEYDOWN`/`WM_KEYUP` + 가상 키 코드로 보내야 한다(`PostMessageInput.key`). 백스페이스는 커서 왼쪽만 지우므로 필드를 비우려면 `VK_END`를 먼저 보낸다.
- **`VK_ESCAPE`는 쓰지 않는다.** 일반 뷰에서 ESC는 팝업을 닫지 않고 "게임을 종료하시겠습니까?" 확인 창을 띄운다(실측, 취소로 복구).
- **입력 전 화면 상태 검증을 의무화한다.** PostMessage는 대상 창의 현재 화면과 무관하게 전달되므로, 기대한 화면이 아니면 엉뚱한 버튼이 눌린다. T12에서 지도 모드가 아닌 상태의 클릭으로 행군(부대 이동) 선택 화면이 열렸다(실행 전 취소). Navigator는 지도 UI 클릭 전 매번 지도 모드 마커를 확인한다.
