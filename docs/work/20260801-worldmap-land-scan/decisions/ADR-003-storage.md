# ADR-003: 저장 구조 — SQLite 수집 원장 + CSV 내보내기

- 상태: 승인 (2026-08-01, 기준선 v1)
- 날짜: 2026-08-01
- 관련 변경 요청: 사용자 결정 Q-03(CSV + SQLite 병행)

## 배경

최대 400만 좌표 레코드를 수 시간에 걸쳐 기록하며, 강제 중단 후 중복·누락 없는 재개가 필요하다(FR-10). 사용자는 CSV와 SQLite 병행을 선택했다.

## 고려한 대안

1. **SQLite를 단일 진실 원천으로 수집하고 완료 시 CSV 내보내기** — 트랜잭션·upsert로 멱등 재개가 자연스럽다.
2. **CSV 직접 기록 + 별도 체크포인트 파일** — 부분 기록 파손·중복 행 방지를 수작업으로 구현해야 함.
3. **양쪽 동시 기록** — 쓰기 2배, 정합성 관리 이중화. 이점 없음.

## 결정

1안. 수집은 SQLite(WAL, `(scan_id,x,y)` PK upsert, 배치 커밋)에만 기록하고, CSV는 완료 시(또는 명시 요청 시) 내보내기로 생성한다. CSV는 UTF-8 BOM, `--split-rows`(기본 100만 행) 분할 옵션을 제공한다.

## 이유

- PK upsert가 재개 시 중복·누락 문제를 구조적으로 제거한다(AC-03).
- WAL 모드는 장시간 쓰기 중 크래시에도 원장 파손을 방지한다.
- CSV를 파생 산출물로 두면 "병행" 요구를 정합성 위험 없이 충족한다.

## 결과와 단점

- 스캔 중간에는 CSV가 존재하지 않는다 — 중간 내보내기 명령으로 보완.
- 저장 공간이 DB+CSV 두 배 — 좌표당 수십 바이트 수준(수백 MB 이내)으로 수용 가능.
