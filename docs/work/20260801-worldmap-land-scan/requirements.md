## 1. 문제와 목적

게임 "삼국지-전략판" PC 클라이언트의 월드맵 전체 좌표를 순회하며 각 좌표의 토지 정보를 추출하고 파일로 저장한다. 게임은 좌표별 토지 데이터를 외부로 제공하지 않으므로, 화면 캡처·이미지 인식·UI 자동 조작으로 정보를 수집하는 stand-alone Windows 프로그램을 개발한다.

## 2. 현재 상태 조사 결과

### 확인된 사실 (제공 이미지 분석)

- 대상 클라이언트: 창 제목 "삼국지-전략판 113.554", 창 크기 **1282x752 고정** (1.png 기준).
- 타일 클릭 시 정보 팝업이 표시된다:
  - 상단 배너: 토지명 (예: `공터`, `Lv.9 목재`, `Lv.7 철광`, `부두`, `공정영`)
  - 배너 아래: `지역-군 (x,y)` 형식의 좌표 (예: `하남-영천군 (989,645)`)
  - 좌측 패널: 세력치, 시간당 자원 생산량, 수비군 병력(중립일 때)
  - 우측 패널: 점령자 정보 — 주군/동맹/전우 (점령된 토지) 또는 맹주/동맹 (성지·부두 등)
- 도적 등장 타일: 팝업에 "도적의 침입" 패널이 추가되고 초상화·종류·레벨·수비군 병력·떠남 시각이 표시된다. *(관찰 사실로만 기록 — 도적 정보 수집은 v0.3에서 범위 제외, Q-05)*
- 강/산 클릭 시 일반 팝업 대신 `강 (880, 654) / 특수 지형, 점령 불가` 형식의 툴팁이 표시된다.
- 2칸이상 건물 클릭 시 건물 전체가 선택되고 좌표는 1개(중심)만 표시된다.
- 좌하단 `지도` 버튼 → 월드맵 모드 진입. 우하단에 좌표 입력란 2개와 `>> 이동` 버튼이 있고, 이동 시 1.png 유사 화면(대상 타일 선택 + 팝업 상태)이 출력된다.
- 줌 레벨이 두 가지 이상 존재한다: 근접 뷰(1.png, 화면당 타일 수십 개)와 광역 뷰(월드맵좌표예시.png, 화면당 타일 수백 개). 광역 뷰에서는 점령 색상 테두리는 식별 가능하나 자원 종류/레벨 텍스트는 표시되지 않는다.
- 1칸건물은 근접 뷰에서 이름 라벨(막사1, 악부, 조폐창 등)이 타일 위에 떠 있다.

### 해석

- 자원토지의 **레벨(Lv.n)은 타일을 클릭해 팝업을 판독해야만** 확정할 수 있다. 화면 스프라이트만으로는 토지 대분류(자원/건물/이동불가)와 점령 색상까지만 식별 가능할 것으로 보인다.
- 좌표 공간이 최대 약 2000×2000 = **최대 400만 좌표**이므로, 전 좌표 클릭 방식은 클릭당 0.7초로 계산해도 30일 이상 걸려 비현실적이다. 이에 따라 스캔 모드를 분리한다(§5 스캔 모드).
- "현재 전체맵보다 큰 좌표 입력 시 최대값으로 강제 변경"되는 동작(월드맵 제약 5)을 이용하면 실제 맵 크기를 자동 감지할 수 있다.

## 3. 대상 사용자

- 게임 플레이어 본인(단일 사용자)이 자신의 PC에서 자신의 계정으로 실행한다.

## 4. 주요 사용 시나리오

1. 사용자가 게임 클라이언트를 실행하고 로그인된 상태에서 추출 프로그램을 시작한다.
2. 사용자가 스캔 모드를 선택한다(v1은 MODE-A만 제공).
3. 프로그램이 맵 크기를 감지하고, 월드맵 좌표를 순회하며 화면을 캡처·인식하여 좌표별 토지 정보를 수집한다. **게임 창이 다른 창에 가려져 있어도 스캔이 진행된다(백그라운드 동작).**
4. 수집된 데이터가 SQLite에 기록되고 완료 시 CSV로 내보내진다. 중단 시 체크포인트에서 재개할 수 있다.
5. 사용자는 저장된 파일을 조회·분석에 활용한다(조회 도구 자체는 범위 밖).

## 5. 기능 요구사항

### 스캔 모드 (사용자 결정 반영)

게임은 두 가지 렌더링 모드를 갖는다(S-2 실측). **전략 뷰**는 중립 타일(자원·공터)을 렌더링하지 않고 점령 타일·소유 건물·지형만 표시한다. **디테일 뷰**는 자원 종류를 스프라이트로 표시하며 점령상태도 함께 읽을 수 있어 전략 뷰 정보의 상위 집합이다. 이에 따라 화면인식 스캔을 A1·A2로 분리한다(DCR-001).

시스템은 다음 4개 모드를 선택적으로 지원한다. **v1(우선 개발)은 MODE-A2만 구현**하고, A1·B·C는 후속 단계에서 구현하되 아키텍처가 이를 수용해야 한다.

| 모드 | 이름 | 수집 범위 | 수집 정보 | 예상 소요(1600²) | 구현 시기 |
|---|---|---|---|---|---|
| MODE-A1 | 전략 줌 스캔 | 전체 맵 | 점령상태, 소유 건물, 지형. 중립 타일은 `중립-미상` | 약 2~4시간(미실측 추정) | 후속 |
| **MODE-A2** | **디테일 줌 스캔** | **전체 맵** | **A1 전체 + 자원 종류·공터·1칸건물·2칸이상건물** | **약 10~15시간** | **v1** |
| MODE-B | 하이브리드 | 전체 맵 + 선별 클릭 | A2 정보 + 선별 대상의 레벨 상세 | — | 후속 |
| MODE-C | 영역 한정 전수 클릭 | 지정 사각 영역 | 전 항목 (레벨 포함) | — | 후속 |

## 7. 범위

**포함(v1):** MODE-A2 디테일 줌 전체 스캔, 스캔 창 크기 설정·복원, 맵 크기 자동 감지, SQLite+CSV 저장, 중단/재개, 진행 표시, 백그라운드 동작, MODE-A1/B/C를 수용하는 구조.

**범위 밖:**
- MODE-A1/B/C의 구현(후속 단계 — 단, 설계는 수용 구조 포함)
- 안드로이드 버전(차기 단계)
- 점령·행군·정찰 등 정보 추출 외의 게임 행위 자동화
- 실시간 변동 추적(본 도구는 1회 스캔 = 1개 스냅샷)
- 저장 데이터의 조회·시각화 도구
- 봇 감지 회피 기능(인간 유사 지연 삽입 수준까지만)

## 8. 제약 조건과 의존성

- 게임 클라이언트가 로그인된 상태로 실행 중이어야 한다.
- *(v2 변경, DCR-001)* 창 크기는 고정이 아니다. 도구가 스캔 시작 시 설정하고 종료 시 복원한다(FR-12). 게임 업데이트로 UI 배치가 바뀌면 캘리브레이션이 필요하다.
- *(S-1 실측 추가, 2026-08-01)* 게임 클라이언트가 관리자 권한으로 실행되는 환경에서는 UIPI로 인해 **본 도구도 관리자 권한으로 실행해야** 입력·창 조작이 가능하다. 캡처(WGC)는 권한과 무관하게 동작한다.
- *(S-1 실측 추가, 2026-08-01)* 동일 제목의 클라이언트 창이 2개 이상이면 제목 기반 캡처 대상 선택이 불안정하므로, 캡처 세션은 HWND 기준으로 바인딩한다.
- 맵 좌표는 0,0부터 시작, 최대 <2000,2000이며 서버마다 다를 수 있다.
- 스캔 중 맵 상태는 계속 변한다(점령 변경, 도적 등장·소멸). 결과는 좌표별 스캔 시점의 스냅샷이다.
