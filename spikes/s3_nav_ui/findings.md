## 상세 발견

1. **입력 프로토콜.** 백스페이스를 WM_CHAR(`\b`)로 보내면 무시된다. WM_KEYDOWN/UP + VK_BACK은 동작하지만 커서 왼쪽만 지우므로 **VK_END를 먼저 보내야** 한다. 이를 빠뜨리면 잔여 문자가 남아 의도하지 않은 좌표로 이동한다(실측).
2. **클램프 시점.** 입력 중에는 5자리도 그대로 표시되고, **포커스가 빠질 때** min(입력, 최대값)으로 강제 변경된다. 따라서 값을 읽으려면 반대 필드를 클릭해 블러시킨 뒤 캡처한다.
3. **맵 크기 감지 대체 방법.** clamp(v)=min(v,max)이므로 "v의 렌더링 == 상한(9999)의 렌더링"인 최소 v가 곧 max다. 폰트에 의존하지 않아 게임 업데이트에 강하고, 0\~2047 이진 탐색 11회로 축당 약 20초.
4. **캡처 바인딩 함정.** `windows-capture`를 제목으로 매칭하면 같은 제목·같은 크기 창을 구분하지 못한다. z-raise 후 제목 매칭 방식이 조용히 다른 창을 잡아, 입력은 A창에 가고 화면은 B창을 보는 상태가 되었다. `window_hwnd` 인자로 **HWND 직접 바인딩**해야 한다(제품 코드 수정 완료).
5. **선택 하이라이트는 앵커로 부적합.** 좌표 점프 후에는 링이 약하거나 늦게 나타난다. 대신 게임이 대상 타일을 고정 화면 위치에 놓는 성질을 앵커로 쓴다 — 템플릿 매칭 교차 검증에서 y 오차 0.6px.
6. **ESC는 위험하다.** 일반 뷰에서 ESC는 "게임을 종료하시겠습니까?" 확인 창을 띄운다(취소로 복구). 제품 코드에서 쓰지 않는다.
7. **오클릭 사고.** 지도 모드가 아닌 상태에서 지도 모드 좌표를 클릭해 **행군(부대 이동) 선택 화면**이 열렸다(ESC로 취소, 행군은 실행되지 않음). S-2 발견 #5가 예견한 위험이 실제로 발생했다. 대책으로 `Navigator`는 매 클릭 전에 지도 모드 마커를 확인하고, 아니면 `NotInMapMode`로 중단한다.
