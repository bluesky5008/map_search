## 핵심 발견 (설계·구현에 반영 필수)

1. **점프 완료 후 게임은 지도 UI를 닫고 디테일 뷰로 복귀한다.** 팬·분류·클릭은
   디테일 뷰에서 일어난다(지도 모드 마커 부재가 정상). 드래그 전 상태 검증은
   지도 마커가 아니라 **계정 HUD 시그니처(프레임 50,55-400,110) 일치 + 지도
   모드 아님**으로 한다(`driver.make_view_check`). 1차 실행에서 지도 마커
   요구가 오탐 중단을 일으켜 교체했다.
2. **선택 팝업은 타일 오른쪽으로도 크게 확장된다.** 실측(점프 팝업, 대상 타일
   중심 기준 상대): 약 **(-275,-200)\~(+355,+140)** — 점령·행군 버튼 열이 오른쪽
   +355px까지. 기록된 `ui.POPUP_RECT_REL`(-600,-170,160,270)과 다르다(팝업
   구성은 타일 종류에 따라 변동). **드래그 시작·종점은 이 영역 밖**이어야
   한다 — 초기 드래그 경로가 행군 버튼 위에서 릴리스되도록 설계되어 있었고
   사전 검증 중단 덕에 실행 전에 발견했다. 커버 오프셋 계산에도 재검토 필요.
3. **팬 이동장은 화면 y에 선형 의존한다(원근 틸트 지면).** 명령 520px 좌팬 시
   실측 콘텐츠 이동: y≈127에서 −444, y≈311에서 −482, y≈466에서 −517px
   (`analyze.py`). 세로 성분은 0(±0.2px). 세로 긴 패치는 단일 위치에 정합하지
   않음(전단 확증, `analyze2.py`). 따름 결론:
   - 콘텐츠 이동 추적은 **관심 대역(분류 대상 y대역)의 패치**로 측정해야 한다.
     균일 평행이동 가정은 팬당 수십 px의 체계 오차를 만든다(G3 1차 해석의 원인).
   - **그리드 기저(E_MX/E_MY)는 국소값**이다 — 앵커에서 화면 y로 먼 셀은 좌표
     예측이 어긋날 수 있다(기존 T11 검증은 y방향 범위가 좁아 미검출). 팬 전환
     구현에서 분류 대역을 앵커 y 근방으로 한정하면 자연히 통제된다.
   - 검증 클릭 실측: 10팬 후 클릭 y대역 누적(−4827px)으로 계산한 예측 타일
     mx=1053.4 vs 게임 팝업 실측 **(1053,586)** — 정합. (산악 타일은 고도
     시차로 클릭 판정이 격자와 어긋날 수 있음 — 기존 사실 #12와 일관)
4. **관성·늦은 정착 없음.** 릴리스 +0.5s부터 잔여 이동 0.0px(NCC 0.99). 정착
   대기 0.8s면 충분하다.
5. **우측 팬 게인 이상(0.62)은 측정 아티팩트였다.** 상단 스트립이 우측 부대
   패널(x≥2255) 밑으로 들어가 생긴 오정합. 좌측 보조 패치로 재면 +444.2로
   좌팬과 대칭(`analyze.py` 질문 3).
6. **겨울(눈) 테마 팝업의 좌표 폰트는 기존 글리프 템플릿과 매칭이 약하다**
   (`analyze3.py` — 전부 '?'). 소스별 변형 템플릿 보강 필요(T14). 스파이크는
   저장 크롭(`g3_strip.png`)의 육안 판독으로 대체했다.

## 소요 참고 (원격 프로토콜 포함, 실제 값은 100방문 실측에서)

- 팬 1회 사이클(캡처 2회 + 드래그 + 정착 0.8s): 원격 \~3.5s. 드래그 실행
  0.36s + 정착 0.8s이므로 로컬(인프로세스)에서는 **\~1.5s + 대역 한정 분류**
  수준이 기대된다(DCR-002 추정 \~2s/방문과 부합).
- 재점프(재앵커): 원격 18.4s — 원격 캡처 왕복이 지배적. 로컬 실측 T12 기준
  3\~4.3s.
